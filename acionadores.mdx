### Transforme comportamento em ações automáticas.

Os Acionadores são uma das partes mais importantes de toda infraestrutura do TrackUp.

Até este ponto da operação, o sistema está capturando dados, rastreando a jornada do visitante e preservando informações importantes sobre toda navegação.

Os Acionadores entram exatamente no momento em que esses dados começam a gerar ações reais.

Eles permitem que o TrackUp monitore comportamentos específicos e execute ações automáticas sempre que determinadas condições forem atendidas.

Em outras palavras:

> O usuário faz algo. O TrackUp reage automaticamente.

# O papel dos Acionadores dentro do ecossistema TrackUp

Durante toda navegação, o usuário gera eventos.

Exemplos:

```text
```

```text
Clique em anúncio

Acesso à página

Visualização de conteúdo

Início de checkout

Conversão
```

Esses eventos podem gerar ações automáticas dentro da plataforma.

Fluxo:

```text
```

```text
Usuário navega
↓
TrackUp registra evento
↓
Sistema analisa regras
↓
Condições são atendidas
↓
Ação é executada
↓
Evento é enviado automaticamente
```

O sistema observa tudo que acontece e toma decisões em tempo real.

# Automação automática ao conectar Pixels 🤖

Na maioria dos casos, você não precisa começar configurando eventos manualmente.

Sempre que um Pixel é conectado ao TrackUp, o sistema cria automaticamente uma estrutura inicial de acionadores padrão.

Isso significa que grande parte do trabalho já começa pronta.

Em outras palavras:

> Você conecta o Pixel e o TrackUp já prepara automaticamente a base inicial de rastreamento.

Nosso objetivo é reduzir trabalho manual e acelerar implementação.

---

# O que o sistema cria automaticamente?

Ao adicionar um Pixel ao projeto, o TrackUp gera automaticamente acionadores responsáveis por registrar eventos essenciais da jornada.

Eventos padrão criados automaticamente:

```text
```

```text
ad_click

page_view

start_checkout

conversion
```

Esses acionadores começam a funcionar imediatamente após a integração.

Sem necessidade de configuração manual inicial.

# Quando criar acionadores manualmente?

Exemplos:

```text
```

```text
Disparar Lead apenas em campanhas específicas

Criar eventos customizados

Enviar eventos condicionais

Criar lógica específica para determinados funis
```

Ou seja:

```text
```

```text
TrackUp cuida do básico automaticamente

Você expande quando precisar de lógica avançada
```

# O que é um Acionador?

Um Acionador é uma automação baseada em condições.

Você define:

```text
```

```text
Quando determinada condição acontecer

↓

Execute determinada ação automaticamente
```

Exemplo:

```text
```

```text
Se o visitante iniciar checkout

↓

Disparar evento InitiateCheckout no Meta Pixel
```

Ou:

```text
```

```text
Se o visitante converter

↓

Enviar evento Purchase automaticamente
```

Você cria a lógica.

O TrackUp executa.

---

# Estrutura de um Acionador

Todo acionador é construído em três partes principais.

```text
```

```text
1. Configurações básicas

2. Condições

3. Ações
```

Essas três etapas definem o comportamento completo da automação.

---

# 1. Configurações básicas

Toda automação começa com uma configuração inicial.

---

### Nome do acionador

Primeiro, defina um nome interno para identificar sua automação.

Exemplos:

```text
```

```text
Disparar Lead Facebook

Purchase Google Ads

Conversão Principal
```

Escolha nomes que deixem claro o objetivo da regra.

---

### Status do acionador

Todo acionador pode ser ativado ou pausado a qualquer momento.

Quando ativo:

```text
```

```text
Sistema monitora normalmente
```

Quando desativado:

```text
```

```text
Regra fica pausada temporariamente
```

Isso permite controlar automações sem apagar configurações.

# 2. Condições 🧠

As Condições definem quando o acionador será executado.

O sistema avalia continuamente os dados coletados durante a jornada do visitante.

Atualmente utilizamos lógica:

```text
```

```text
AND (E lógico)
```

Ou seja:

> Todas as condições precisam ser verdadeiras para o acionador ser executado.

Cada condição possui três partes.

---

### Variável

Qual informação será analisada.

Exemplo:

```text
```

```text
Tipo de evento
```

---

### Operador

Como o sistema fará a comparação.

Exemplo:

```text
```

```text
Igual

Diferente

Contém

Maior que

Menor que
```

---

### Valor

O valor que será comparado.

Exemplo:

```text
```

```text
start_checkout
```

Exemplo completo:

```text
```

```text
Variável → Tipo de evento

Operador → Igual

Valor → start_checkout
```

Resultado:

```text
```

```text
Executar apenas quando start_checkout acontecer
```

Você pode adicionar múltiplas condições.

---



Essas informações ajudam a enriquecer os dados enviados para a plataforma.

# Opções de disparo

Ao configurar uma ação, você escolhe como o evento será enviado.

Atualmente existem dois modos.

---

### Disparo via servidor (CAPI)

Quando ativo, o evento é enviado diretamente pelos servidores do TrackUp.

Fluxo:

```text
```

```text
TrackUp Server
↓

API da plataforma
```

Benefícios:

- \
  Maior confiabilidade\
- \
  Menor bloqueio por adblockers\
- \
  Melhor atribuição\
- \
  Dados mais consistentes\

Esse método é altamente recomendado.

---

### Disparo via navegador

Quando ativo, o evento é enviado diretamente pelo navegador do visitante.

Fluxo:

```text
```

```text
Visitor Browser
↓

Pixel Script
```

Pode ser útil em cenários específicos onde a plataforma exige execução client-side.
