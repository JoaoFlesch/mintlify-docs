Agentes de IA e automações com LLM usam o Trackup pela mesma API de qualquer integração, com uma chave de API no header X-Api-Key. Se você usa Claude, ChatGPT, Cursor ou VS Code, o caminho mais simples é o servidor MCP.

O que um agente pode fazer

ObjetivoEndpointsPermissões
Registrar vendas, reembolsos e chargebacks de um CRM ou checkoutPOST /v1/conversions, /refunds, /chargebacksconversion.create
Criar visitantes e eventosPOST /v1/visitors, /requestsvisitor.create, request.create
Ler métricas e listasGET /v1/projects/{id}/analytics/overview, /conversions, /visitors, /requestsanalytics.read, conversion.list, visitor.list, request.list
Acompanhar e ajustar campanhas da Meta/v1/ads-manager/{projectId}/summary, /table, /entities/{id}/status, /budgetads-manager.read, ads-manager.update
Configurar projetosPixels, acionadores, domínios, links, páginas, fontes de tráfego, plataformas de venda, filtroAs do recurso, como page.create

Cobrança, membros, gestão de chaves, exclusão de projeto e conexões OAuth não estão disponíveis para chaves.

Configurar o acesso

Anote os endpoints e as permissões da tabela acima. Um agente que registra vendas precisa só de conversion.create. Um agente de relatórios só lê.

Em Configurações › Chaves de API › Nova chave, dê um nome como Agente de relatórios, escolha só os projetos necessários e marque só as permissões anotadas.

Salve em uma variável de ambiente ou no cofre de segredos da plataforma do agente. A chave fica no código que faz a requisição, nunca no prompt, na memória do modelo ou em logs.

 curl https://api.trackup.me/v1/projects \ -H "X-Api-Key: $TRACKUP_API_KEY"

A resposta lista os projetos que a chave acessa. 401 indica chave ausente ou inválida; 403, chave revogada, expirada ou sem permissão.

Em Chaves de API › Ver histórico, veja cada chamada do agente com o corpo enviado e a resposta.

Instruções para o agente

Cole este bloco nas instruções do agente:

Você opera o Trackup pela API REST. Base: https://api.trackup.me/v1. Autenticação: header X-Api-Key. Corpos e respostas em JSON. Listagens retornam { "data": [...], "count": n } e aceitam page e limit. Datas de consultas: YYYY-MM-DD, dias no fuso do time. Projetos: GET /projects lista os projetos acessíveis; use o id em /projects/{id}/... Ingestão (POST /visitors, /conversions, /refunds, /chargebacks, /requests): envie projectId no corpo, exceto quando a chave tiver um único projeto. Conversões: value é obrigatório. Envie transactionId; 409 significa que a transação já foi registrada. Erros: 401 chave inválida; 403 sem permissão ou chave revogada; 404 recurso fora do escopo; 409 conflito; 422 corpo inválido (veja o objeto errors). Peça confirmação a uma pessoa antes de pausar campanhas, mudar orçamento, publicar ou apagar. Referência: https://docs.trackup.me/api

Boas práticas

  • Uma chave por agente, para revogar e auditar separado.
  • Projetos restritos: um agente de um cliente não enxerga os outros.
  • Validade em testes: chaves de experimento expiram sozinhas.
  • Aprovação humana para ações que mexem em dinheiro ou no que está no ar.
  • Trate 4xx como resposta: o agente deve ler a mensagem e corrigir a chamada, não repetir.
