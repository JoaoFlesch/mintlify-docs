Toda visita passa pelo seu domínio no Trackup antes de chegar à página. Nesse ponto o Trackup registra quem é o visitante e de onde ele veio, aplica o filtro, dispara os eventos para os pixels e guarda um ID que acompanha a pessoa até a venda.

{{icon:arrow}}

{{icon:arrow}}
5. Vendawebhook com o ID do clique
  1. Clique. A pessoa clica no anúncio. A URL leva os parâmetros de UTM da fonte de tráfego e o Click ID da plataforma (fbclid, gclid, ttclid).
  2. Requisição. O acesso chega ao seu domínio. O Trackup cria uma requisição com origem, UTMs, dispositivo, país e pontuação de bot, e aplica as regras do Filtro.
  3. Página. A página é servida e o evento page_view é gerado. Os acionadores enviam o evento para os pixels pelo servidor.
  4. Checkout. O visitante clica no botão de compra, que aponta para o link da oferta. O Trackup gera start_checkout e repassa ao checkout o ID da requisição e as UTMs.
  5. Venda. A plataforma de venda envia o webhook de compra com o ID de volta. O Trackup liga a venda ao clique, gera o evento conversion e envia para os pixels.

Conceitos

Projeto

Agrupa tudo de uma operação: domínios, pixels, páginas, testes, regras de filtro e relatórios. Cada projeto tem uma moeda fixa. Um time pode ter vários projetos.

Página e link

Toda página tem um link próprio no seu domínio, como lp.seudominio.com/oferta. Esse é o endereço que você divulga. Páginas com finalidade Landing ficam em Páginas; páginas com finalidade Checkout são as Ofertas.

Um Teste A/B é um link extra que divide o tráfego entre duas ou mais páginas.

Requisição e visitante

Uma requisição é cada acesso a um link. Um visitante é a pessoa por trás das requisições, reconhecida entre visitas. Um visitante pode ter várias requisições, eventos e conversões.

Evento

Uma ação no funil. Os eventos nativos são ad_click, page_view, start_checkout e conversion. Você também pode enviar eventos customizados, como video_started ou lead_form_submitted, com o script.

Pixel e acionador

O pixel guarda as credenciais da plataforma de anúncios. O acionador define quando enviar um evento para esse pixel, por exemplo "toda conversão vinda da Meta".

Atribuição e Click ID

Atribuição é descobrir qual campanha gerou cada venda. O Trackup faz isso guardando o ID de cada requisição e repassando esse ID ao checkout em um parâmetro que a plataforma de venda devolve no webhook (por exemplo sck na Kiwify ou src na Monetizze). Quando o ID não volta, a venda aparece como Click ID ausente e fica sem campanha.

UTMs

Parâmetros na URL que descrevem a origem do clique: utm_source, utm_medium, utm_campaign, utm_content e utm_term. O Trackup preserva as UTMs entre páginas e as envia ao checkout.

Server-side

Os eventos são enviados do servidor do Trackup direto para a API de conversões de cada plataforma. Bloqueadores de anúncio e restrições do navegador não impedem o envio.

Por que o domínio importa

O rastreamento acontece no domínio do projeto. Por isso:

  • todo tráfego pago deve entrar por um link do Trackup;
  • os botões de compra devem apontar para o link da oferta, nunca para o checkout original;
  • páginas hospedadas fora do Trackup precisam do script de rastreamento.
Coloque esse fluxo para funcionar na prática. Veja cada etapa registrada nos logs.
